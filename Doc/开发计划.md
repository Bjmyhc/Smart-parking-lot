## 项目概述与系统架构

### 1.1 系统架构（物理拓扑）

```
STM32节点1 (车位检测+LoRa, 地址0x0001)  ----+
                                             |
STM32节点2 (车位检测+LoRa, 地址0x0002)  ----+----> LoRa 无线 <----> ESP8266 网关 (地址0x0000)
                                             |                                  |
STM32节点N (车位检测+LoRa, 地址0x000N)  ----+                        WiFi <---> OneNET (网关+子设备模式)
                                                                     |
                                                                  OLED (SDA=D5/SCL=D6)
                                                         SoftwareSerial(9600) 接 LoRa
```

ESP8266 网关负责：轮询各节点 → 收 LoRa 二进制帧 → 解析节点数据 → 代子设备上报 OneNET → 接收平台下行命令 → 通过 LoRa 控制节点。

### 1.2 LoRa 通信方案选型（2026-08-08 定版）

| 方案 | 说明 | 评估 | 占用带宽 | 复杂度 | 结论 |
|---|---|---|---|---|---|
| 简单+ASCII CSV (旧) | LoRa 直接收发字符串 `$N,1,2,3...` | 实现简单，但 >2 节点会碰撞 | ASCII 40字节/帧 | 低 | 放弃 |
| **定点传输+二进制+轮询调度 (定版)** | LoRa 帧头 [AddrH][AddrL][CH] + 帧类型字节 `0xA1/0xB1` + `#pragma pack(1)` 结构体 memcpy，按序轮询 AT+DATAx 指令 | **无碰撞**，轮询不丢包 | 二进制 11 字节/帧，空口占用 <1/4 | 50+ 行轮询代码 | **采用** |

## 硬件方案

### 2.1 网关选型对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| NodeMCU 1.0 (ESP-12E) | GPIO多、USB供电、便宜 | 体积稍大 | **采用** |
| Wemos D1 mini | 体积小 | GPIO较少 | 备选 |

> 后续如需升级可换 ESP32：3 个硬串口，240MHz，520KB RAM，性能提升 90%+，代码兼容性高。

### 2.2 硬件接线

```
ESP8266 (NodeMCU)     LoRa模块(发送端)
D2 (GPIO4)        <-- TX        (LoRa模块TX -> ESP RX)
D1 (GPIO5)        --> RX        (ESP TX -> LoRa模块RX)
3.3V              --> VCC
GND               --> GND

USB                --> 调试串口 (Serial, 115200)

ESP8266 (NodeMCU)     OLED (0.96" SSD1306)
D5 (GPIO14)       --> SDA         (I2C 数据)
D6 (GPIO12)       --> SCL         (I2C 时钟)
3.3V              --> VCC
GND               --> GND

GPIO0 (板载 FLASH 按键)     长按 3s 进入 AP 配网模式
```

- LoRa 用 SoftwareSerial (9600bps)，避免占用 USB 调试串口
- LoRa 发送采用**定点传输**，目标节点地址由代码控制
- OLED 接 D5(SDA)/D6(SCL)，与其他 I2C 设备无冲突

### 2.3 LoRa 模块配置 (2026-08-09 确认: DX-LR22-433T22D)

网关端与节点端 LoRa 模块均为 **DX-LR22-433T22D**，需通过 **AT 指令**配置一致。
配置方法: 模块接串口调试 + 模块 AUX 引脚接地（进入配置模式），USB-TTL 9600 连接，发送 `\r\n` 结尾的 AT 指令：

| 指令 | 含义 | 说明 |
|---|---|---|
| `AT+MODE1` | 设置传输模式 | 0=透传, 1=定点, 2=唤醒 |
| `AT+LEVEL6` | 设置空中速率 37500bps | 参考项目空中速率 38.4K |
| `AT+CHANNEL00` | 设置信道 0 = 433.15MHz | 所有设备一致 |
| `AT+BAUD3` | 设置串口波特率 9600 | 模块端固定 |
| `AT+OPENKEY1` | 开启加密 | 可选 |
| `AT+KEY12345` | 设置密钥 12345 | 可选，所有设备一致 |
| `AT+RESET` | 复位模块使配置生效 | 配置完成后必须 |

节点地址分配（模块配置时设置）：

| 设备 | 配置指令 | 地址 |
|---|---|---|
| 网关 | `AT+MAC00,00` | 0x0000 |
| 节点1 | `AT+MAC00,01` | 0x0001 |
| 节点2 | `AT+MAC00,02` | 0x0002 |

> ?? **DX-LR22 信道定义与参考项目 E19 不同**：DX-LR22 的 `0x17`=468.15MHz，
> `0x00` 对应 433.15MHz，所以 `LORA_CHANNEL` 配置为 `0x00`。
> 定点传输帧格式为 `[AddrH][AddrL][CH]+数据`，注意 CH 在数据前。
> 节点端必须与网关端完全一致（`AT+MODE1` + `AT+MAC`），否则收不到。

### 2.4 供电

- USB 供电 (5V 经板载 3.3V LDO 供 ESP8266)
- LoRa 模块接 NodeMCU 3.3V 引脚
- 注意: LoRa 发射瞬间电流较大，建议单独供电或加电容。

### 3.3 业务流程

```
数据轮询 (网关 → 节点):
  1. 网关定时发起: lora_sendCommand(AT+DATA1) 经 LoRa 定点发送给节点1
  2. 节点收到命令  → 读取传感器 → 经 LoRa 回传 [0xB1 + NodeData结构体]
  3. ESP8266 lora_tick() 收到 → lora_handleFrame() 解析 0xB1 帧头
  4. updateNodeFromRaw() 更新节点数据 → onenet_uploadAll() 代子设备上报 OneNET

命令下发 (平台 → 节点):
  1. OneNET 平台 MQTT PUBLISH → mqtt_callback() 收到下行命令
  2. Topic 匹配: thing/sub/property/set → 按 identity 定位子设备
  3. 解析参数(如 LedEnable=false)
  4. lora_sendControl(AT+LedEnable=0) 经 LoRa 定点下发到节点
  5. 节点执行 → 回传 [0xC1 + 执行结果]
  6. 网关收到 0xC1 → 解析 → onenet_replySet() 回复 OneNET

节点证书注册 (首次接入):
  1. 网关发起: lora_sendCommand(AT+CER1) 向节点1查询证书
  2. 节点回传 [0xA1 + NodeCert结构体] (ProductKey/DeviceName/AccessKey)
  3. 网关记录证书并代节点上线 OneNET (thing/sub/login, 按网关+子设备模式)
  4. OneNET 返回 code:200 → 子设备上线成功 → 后续轮询改发 AT+DATAx
```

### 3.4 事件调度机制（对应参考项目 ActiveEvent）

```
每轮 loop() 执行:
  ├─ lora_tick()              高频: 轮询调度+数据接收(最优先)
  ├─ onenet_loop()            高频: MQTT 保活+接收下行
  ├─ checkNodeTimeout()       高频: 节点超时离线检测
  └─ activeEvent()            低频: 定时任务
       ├─ 每15s:   定时批量上报节点数据(若有变化)
       ├─ 每60s:   MQTT PINGREQ 心跳 (标志位检测假死)
       └─ 每50轮:  已注册节点夹发 AT+CER 校验证书(同地址换节点检测)
```

### 3.5 系统事件标志位(参考参考项目 main.h)

参考项目用 32 位事件标志位，O(1) 判断系统状态。

```c
// 系统事件 (高位16位)
#define SYS_EVENT_MQTT_CONNECTED    0x80000000  // MQTT 已连接(CONNACK收到)
#define SYS_EVENT_PING_SENT         0x40000000  // PINGREQ 已发, 等 PINGRESP
#define SYS_EVENT_CONFIG_PORTAL     0x20000000  // AP 配网模式

// 节点在线位 (低位16位) 动态位, 由 node_data.cpp 维护
#define SYS_EVENT_NODE1_ONLINE      0x00000001  // 节点1 在线
#define SYS_EVENT_NODE2_ONLINE      0x00000002  // 节点2 在线
#define SYS_EVENT_NODE3_ONLINE      0x00000004  // 节点3 在线
// ... NODE_N_ONLINE = (1 << (N-1)), 最多16节点
uint32_t sysEventFlag = 0;
```

### 3.6 PING 心跳检测机制(参考参考项目标志位方案)

用来检测"WiFi 还连着、但 MQTT TCP 半开"的假死连接。

```
每60s:
  if (PING_SENT 标志已置位)
      说明上次 PING 没收到 PINGRESP → MQTT 掉线 → 断开+清标志 → 走重连
  else
      发送 PINGREQ 并置位 PING_SENT

收到 PINGRESP:
  清除 PING_SENT 标志
```

### 3.7 CONNACK 错误码处理(参考参考项目 wifi.c)

PubSubClient `connect()` 返回 false 时检查 `state()`，分类提示：

| code | 含义 | 处理 |
|---|---|---|
| 0 | 已连接 | 订阅Topic + 代节点上线 |
| 1 | 协议版本错误 | 检查库版本 |
| 2 | 客户端标识被拒绝 | 检查设备名 |
| 3 | 服务器不可用 | 稍后重试 |
| 4 | 用户名/密码错误 | 检查 Token |
| 5 | 未授权 | 检查 Token |

## LoRa 通信协议

### 4.1 LoRa 定点传输帧格式

固定点对点传输，完整一帧由 3 字节前缀 + 数据构成：

```
[目标地址H][目标地址L][信道] + [业务数据]
```

### 4.2 下行命令 (网关 → 节点, ASCII)

| 命令 | 格式 | 说明 |
|---|---|---|
| 查询证书 | `[AddrH][AddrL][CH]AT+CER1\r\n` | 查询节点1的OneNET证书 |
| 查询数据 | `[AddrH][AddrL][CH]AT+DATA1\r\n` | 查询节点1传感器数据 |
| 控制输出 | `[AddrH][AddrL][CH]AT+LedEnable=0\r\n` | 设置节点1的LED开关 |
| OTA查询版本 | `[AddrH][AddrL][CH]AT+VER1=xxx\x00[sizeH][sizeL]` | OTA 版本查询 |

### 4.3 上行帧头 (节点 → 网关, 二进制)

| 帧头 | 附带数据结构 | 说明 |
|---|---|---|
| `0xA1` | NodeCert 结构体 | 节点1证书上报 |
| `0xA2` | NodeCert 结构体 | 节点2证书上报 |
| `0xA_N` | NodeCert 结构体 | 节点N证书上报 |
| `0xB1` | NodeData 结构体 | 节点1传感器数据 |
| `0xB2` | NodeData 结构体 | 节点2传感器数据 |
| `0xB_N` | NodeData 结构体 | 节点N传感器数据 |
| `0xC1` | 4字节执行结果 | 节点1命令确认 |
| `0xD1` | 无 | 节点1 OTA接收成功 |
| `0xE1` | 无 | 节点1 OTA要求重发 |

> **关键设计**: 帧头包含节点号(0xB1=节点1数据)，配合定点传输可以自动识别数据来源，无需复杂校验。结构体直接 memcpy 传输。

### 4.4 NodeData 结构定义(参考 Attribute_CB)

```c
#pragma pack(push, 1)
typedef struct {
    uint8_t  ParkStatus;      // 车位状态: 0=空闲, 1=有车, 2=僵尸车
    uint8_t  GeoMagnetic;     // 地磁检测: 0/1
    uint16_t Ultrasonic;      // 超声波距离: 0~400 cm
    uint32_t OccupiedTime;    // 占用时长: 秒
    uint8_t  LED;             // LED状态: 0/1
    uint8_t  LedEnable;       // LED使能: 0/1
} LoraNodeData_t;             // 共 10 字节, 经 LoRa 二进制传输
#pragma pack(pop)
```

### 4.5 NodeCert 结构定义(参考 AliyunInfo_CB)

```c
#pragma pack(push, 1)
typedef struct {
    uint8_t  valid;           // 有效标志
    char     ProductKey[12];  // OneNET 产品ID
    char     DeviceName[33];  // OneNET 设备名称
    char     AccessKey[33];   // OneNET 设备密钥(鉴权用, 不公开)
} LoraNodeCert_t;
#pragma pack(pop)
```

### 4.6 OTA 传输帧格式(参考参考项目)

```
[AddrH][AddrL][CH][0x5A][0xA5][包序号H][包序号L][128字节固件数据]
```

- 每帧 128 字节数据 + 7 字节包头 = 135 字节，小于 LoRa 240 字节缓存
- 节点收到后回复 0xD1(成功) 要求发下一包，或 0xE1(失败) 要求重发

### 4.7 OTA 升级流程 (参考参考项目 wifi.c L223-L444)

#### 网关自身 OTA

```
1. OneNET 下发 OTA 消息 → 解析固件大小/版本号/streamId
2. ESP8266 从 OneNET 下载固件 (256B/包) → 暂存 LittleFS
3. 下载完成 → 校验固件版本 → 调用 ESP.restart()
4. ArduinoOTA BootLoader 写入 Flash
```

#### 子设备 OTA (规划中)

```
阶段1: 网关 → 云端
  1. OneNET 下发子设备OTA消息 (module=SUB1/SUB2/SUB3)
  2. 解析固件大小/版本号 → 置位 OTA_EVENT
  3. 网关从 OneNET 下载固件 (256B/包) → 暂存 LittleFS

阶段2: 网关 → 子设备(LoRa 分包下发)
  5. 组帧: [AddrH][AddrL][CH][0x5A][0xA5][包序号H][包序号L][128B数据]
  6. LoRa 定点发送 → 子设备接收写入
  7. 收到 0xD1: 包序号+1 → 发送下一包
  8. 收到 0xE1: 重发当前包
  9. 无响应: 超时重试(最多3次)
  10. 全部发完 → 上报子设备版本号给 OneNET

阶段3: 子设备重启
  11. 子设备接收全部固件 → 写入 Flash W25Qxx
  12. 校验通过 → 重启 → BootLoader 引导新固件
```

#### OTA 超时与重试机制 (参考参考项目)

- OTA 总超时: 120s，超时后退出并清除 OTA_EVENT
- 分包超时: 每包 3 秒，3 次超时则放弃本次 OTA
- OTA 期间暂停其他业务，避免 LoRa 空口冲突

### 6.3 参考项目遗留实现细节

#### 6.3.1 串口环形缓冲区方案(参考项目串口处理)

参考项目为串口配置了双指针环形缓冲区：

```
UsartRxDataInPtr  写入指针 (中断接收时)
UsartRxDataOutPtr 读出指针 (主循环取出时)
UsartRxDataEndPtr 结束指针 (满时回绕)
```

ESP8266 Arduino 用 Serial 自带环形缓冲区，无需自己实现，逻辑一致。

#### 6.3.2 DMA 发送 + 定时器刷新 (参考项目串口发送)

参考项目使用 DMA + 100ms 定时器刷新发送：

```c
if((UsartTxDataOutPtr != UsartTxDataInPtr) && (TxCpltflag == 0) && (HAL_GetTick() - TxTimer > 100))
```

ESP8266 SoftwareSerial 不支持 DMA，用每轮 loop 检测待发送缓冲 + 间隔发送，
避免连续占用 LoRa 空口导致丢包。

#### 6.3.3 AUX 载波检测方案(参考项目 LoRa 模块)

参考项目用 LoRa 模块 AUX 引脚判断模块状态：

- AUX=1：模块空闲，可发送/接收
- AUX=0：模块忙，正在处理

ESP8266 未使用 GPIO 检测 AUX（模块自带 LBT 载波监听），如需更可靠的
防碰撞可后续接 AUX 引脚检测发送时机。

## 注意事项与踩坑记录

### 9.1 LoRa 并发与轮询

本项目采用轮询方案，无需 LBT，但需注意：

1. **LBT**：如后续节点变多，LoRa 模块的 LBT 可避免碰撞，但轮询已够用
2. **轮询周期**：按协议各节点独立轮询，不会互相干扰
3. **丢包**：轮询机制容忍单次丢包，下轮自动补查

### 9.2 SoftwareSerial 兼容性

ESP8266 SoftwareSerial 对波特率和中断比较敏感：

- LoRa 模块串口波特率固定为 9600，参考项目空中速率 9600 不适用
- 如果波特率 115200 不稳定，建议换 ESP32（3 个硬串口）

### 9.3 MQTT 缓冲区大小

子设备批量上报(pack/post)的 JSON 最大 300 字节(identity + 6个属性值)：

- 使用 `mqtt.setBufferSize(2048)`，onenet_handler.cpp 已设置
- 平台下行属性设置(set) payload 通常 < 200 字节，默认缓冲区 768 字节够用

### 9.4 OneNET Token 有效期

网关 Token 的 `et=1815919855` (2027年到期)，到期后需重新生成：

- 修改 Token 在 platform_cfg.h
- 子设备 Token 存 LittleFS，到期后重新获取

### 9.5 ESP8266 内存

ESP8266 可用 RAM 约 40KB，注意控制：

- 子设备数据数组：10 个 × sizeof(NodeData) ≈ 100 字节
- 子设备证书数组：10 个 × sizeof(NodeCert) ≈ 1KB
- ArduinoJson StaticJsonDocument<512> 占用 512 字节
- MQTT + WiFi 协议栈占用约 20KB
- 其余 22KB 留给应用逻辑
- 若内存不足 > 20%，需检查 `ESP.getFreeHeap()`

### 9.6 未来升级 ESP32 适配表

| 功能点 | ESP8266 | ESP32 |
|---|---|---|
| WiFi 库 | `ESP8266WiFi.h` | `WiFi.h` |
| LoRa 串口 | `SoftwareSerial` | `Serial1` (硬串口) |
| Flash 存储 | LittleFS (4MB) | LittleFS (8~16MB) |
| WebServer | `ESP8266WebServer` | `WebServer` |
| 代码兼容性 | 基准 | 基本可移植 |

### 9.7 AP 配网与 MQTT 冲突

AP 配网期间 ESP8266 同时开启 AP 和 WiFi STA，MQTT 不会连接：

- 配网页面显示状态时不连 MQTT，仅显示节点在线信息
- 配网成功自动切换回 STA 模式
- 子设备证书存在 LittleFS，配网不影响证书

### 9.8 OTA 与 LoRa 冲突

子设备 OTA 升级会占用 LoRa 空口，需注意：

- OTA 期间暂停其他 LoRa 轮询，避免冲突
- OTA 分包间隔适当加长
- 子设备 OTA 完成后重启会自动重新注册

### 9.9 OLED 8x8 字库 PROGMEM 陷阱 (重要!)

8x8 点阵字库存 `PROGMEM` 后，ESP8266 core/Flash 的字节对齐要求，直接 `[]` 访问
`.irom.text` 段会触发 `Exception(3) LoadStoreError` 导致无限重启。

- 方案: 字库约 760 字节直接放 RAM，代价可接受
- 镜像问题: 字库位序 bit0=最左列, 必须用 `drawPixel` 按 `1 << col` 绘制,
  不能用 Adafruit `drawBitmap`(bit7=最左列), 否则整体镜像

### 9.10 编码规范 (重要, 2026-08-09 新增)

| 代码端 | 工具链 | 编码 | 说明 |
|---|---|---|---|
| **网关端** (Gateway/) | Arduino IDE | **UTF-8** | Arduino IDE 2.x 用 UTF-8 编码, 写 GBK 会乱码或编译错误 |
| **节点端** (STM32 节点) | Keil MDK | **GB2312** (ANSI/GBK) | Keil 默认用 GB2312 编码显示中文, 写 UTF-8 会乱码 |

注意规范:
- 网关端全部代码用 UTF-8: `Gateway.ino` + 所有 `.cpp/.h`
- 节点端全部代码用 GB2312: `lora_node.c/.h` 等
- 两端共享协议文件 `lora_protocol.h` 在网关端属于**网关代码**, 用 UTF-8
- 建议**不带 BOM** 的 UTF-8 (带 BOM 会导致一些工具解析异常)
- 检查方法: 用 VS Code / Trae 打开, 中文显示正常 = 编码正确
- 曾发生: 编码错误导致中文永久丢失(开发计划.md 损坏事故), 务必用正确工具保存
  (Arduino IDE 2.x / VS Code / Trae 保存网关端; Keil 保存节点端)
