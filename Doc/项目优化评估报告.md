# 项目优化评估报告

- 版本：v1.1（2026-09-10 修订）
- 评估范围：Gateway / Node / User / PlateRecognition / Mcp_Tool / Tool / Doc / shared 八大模块
- 评估维度：代码质量、性能、安全、可维护性、架构、技术债务、文档

> 说明：本报告中安全类问题仅描述"位置 + 问题类型"，不展示任何密钥/口令具体值。

> **修订记录（v1.0 → v1.1，2026-09-10）**：v1.0 中部分条目转引了历史文档结论而未核对当前代码，导致把已修复项判为缺陷。本次按代码实际状态逐条复核并更正：
> - N1（超声波最坏阻塞 400ms）→ **已修复**，双重超时兜底，最坏约 200ms 安全返回；
> - N2（地磁 `while(1)` 死循环）→ **误报**，该循环为校准诊断工具驻留，不在主运行路径；
> - N3（串口最坏阻塞 950ms）→ **已修复**，每字节死等 TC/TXE 均限 50ms（保留 296B 栈缓冲的可维护性项）；
> - G1（启动阻塞 20s+）→ **修正为分段非阻塞式启动**，最坏约 15s 且界面全程可观测；
> - N4（BootLoader 串口无超时）→ 严重度**下调**：无上限死等属实，但 Boot 已开 IWDG（约 4s）兜底，实际表现为复位循环而非永久挂死；
> - N5（异常处理器空转）→ **仍成立**（空 `while(1)` 无现场、无复位，配合 IWDG 表现为静默复位循环，调试信息全丢）；
> - U1/S1/S2（凭据硬编码且未纳入 `.gitignore`）→ **仍成立**。
> - **断电自愈 → 由"延后项"更正为"已闭环"**：节点来电滞留 Boot 回 `PONG,BOOT`，网关 `ota_autoDispatch()` 自动续传（固件保留至 `PONG,APP`，自愈预算 3 次），见 [技术待办-延后事项.md](技术待办-延后事项.md) 现状核实。
> - **总体评分由 84 上调至 87**：断电自愈闭环 + N4 严重度下调（IWDG 兜底，非永久挂死）。
> - 第八节优先顺序同步更新。**仍成立的真实缺陷**：N4（BootLoader 串口无超时，严重度降为低）、N5（异常处理器空转）、U1/S1/S2（凭据硬编码）。

## 一、总体结论

架构上采用"多端分层 + 协议单一事实源"（[lora_protocol.h](../shared/lora_protocol.h) 双端共享），设计思路清晰。S30–S32 迭代后网关侧通信可靠性已明显闭环（PONG 兜底重发、先代下线后 PING 的注册顺序、阈值命令连续入队），[通信架构重构方案.md](通信架构重构方案.md) 对迭代做了版本化记录，文档习惯良好。

**总体评分：87 / 100（B+）——可用可运行，通信可靠性已明显闭环（含升级断电自愈），剩余主要风险为安全凭据卫生与 App 功能完整度**

主要风险集中在三处：

1. **凭据卫生**：多个源文件硬编码密钥且未被 `.gitignore` 隔离，泄露即失控；
2. **Node 实时性**：早期同步阻塞（超声波/串口）已于 2026-09 加装超时保护闭环，现有风险收敛至异常处理器与 BootLoader 串口发送（见 N1/N3/N4/N5）；
3. **App 功能完整度**：部分核心功能为假实现 / 占位数据，与设备端能力不对等。

## 三、Node（STM32F103C8T6 固件 + BootLoader）

### 高严重度

| N5 | 异常处理器全部为空 `while(1)` 无诊断（[stm32f10x_it.c](../Node/Firmware/Main/stm32f10x_it.c)） | HardFault 后静默挂死，无定位手段 | 在异常处理中保存现场（PC/LR/寄存器）到保留 RAM 或通过串口打印错误码 | 现场问题可定位，大幅降低调试成本 | 低 |
