## 一、系统概览

```
STM32 节点 (传感器+LoRa) ←→ LoRa 定点 → ESP8266 网关 ←→ WiFi → OneNET 云平台
```

每车位一个 STM32 节点（超声波+地磁传感器），通过 LoRa 无线与 ESP8266 网关通信，网关汇聚数据后通过 MQTT 上报 OneNET 云平台。平台可下发控制命令（如 LED 开关），实现远程车位监控。

---

## 二、项目背景与价值

### 2.1 为什么做这个项目

传统停车场管理大多依赖人工巡查或单一摄像头方案，存在几个痛点：

- **车满难找**：车主不知道哪个车位空闲，进场后兜圈找位
- **数据不联网**：停车场管理者看不到实时占用率，无法做运营决策
- **设备部署难**：布线成本高，改造老旧停车场尤其困难

本项目提供一套**低功耗、免布线、远距离**的车位检测方案：每个车位一个独立检测节点，无线组网，云端统一管理。

### 2.2 方案价值

| 价值点 | 说明 |
|--------|------|
| **无线免布线** | LoRa 433MHz 远距离通信，一个网关覆盖整层车库，无需网线/电源布线到每个车位 |
| **低功耗低成本** | 节点用 STM32 + 超声波 + 地磁，成本低、待机功耗小，适合大规模部署 |
| **实时云端可视** | 车位状态、占用时长实时上报 OneNET，手机/电脑随时查看 |
| **远程控制** | 平台可下发 LED 控制命令，实现指示灯联动、异常定位 |
| **易维护** | 节点掉线自动检测、自动恢复，网关断网自动重连，无需人工干预 |

### 2.3 适用场景

- 社区/园区地下停车场：车位引导、占用率统计
- 商场/写字楼停车场：找位引导、收费辅助
- 路侧停车：占用检测、违停提醒
- 教学/实训：完整物联网通信链路（传感器→LoRa→网关→MQTT→云平台）演示平台

## 三、功能特性

- **多车位检测**：超声波 + 地磁双重检测，自动判定车位状态（空闲/有车/僵尸占用）
- **LoRa 无线通信**：433MHz 远距离，网关轮询避免碰撞，二进制结构体传输高效省电
- **OneNET 云平台**：MQTT 长连接，子设备独立物模型，数据实时上报
- **远程控制**：平台下发 LedEnable 命令，毫秒级到达节点执行
- **自动恢复**：WiFi 断线重连、节点离线检测、子设备自动重新上线
- **AP+Web 配网**：首次上电自动进入配网模式，长按板载 FLASH 键（GPIO0）5 秒可重新配网，配置持久化到 LittleFS
- **OLED 集中显示**：网关 0.96" 双色屏集中显示 MQTT 连接、节点在线状态、车位状态与停车时长（节点端不再挂 OLED）

## 四、硬件清单

| 硬件 | 数量 | 说明 |
|------|------|------|
| **NodeMCU ESP-12E** | 1 个 | 网关主控，运行 Arduino 程序 |
| **STM32F103 开发板 (BH-F103)** | 每车位 1 个 | 节点主控，运行 Keil 程序 |
| **DX-LR22-433T22D LoRa 模块** | 网关 1 个 + 每节点 1 个 | 433MHz 定点传输 |
| **HC-SR04 超声波模块** | 每节点 1 个 | 测距 2~400cm |
| **QMC5883P 地磁传感器** | 每节点 1 个 | 磁场检测 |
| **0.96" OLED (I2C)** | 网关 1 个 | 集中显示网关与各节点状态（SDA=D5, SCL=D6） |
| **LED 指示灯** | 每节点 1 个 | 可远程控制开关 |

## 五、接线说明

> 以下为经过验证的完整接线表，按表格连线即可。所有模块注意**共地**（GND 相连）。
> 引脚定义与代码配置文件一一对应（网关见 `hw_cfg.h`，节点见各 `bsp_*.h`）。

### 5.1 网关（ESP8266 NodeMCU）接线

| 网关引脚 | 方向 | 连接到 | 说明 |
|----------|------|--------|------|
| **D2 (GPIO4)** | ← 输入 | LoRa 模块 **TX** | SoftwareSerial RX，收 LoRa 数据 |
| **D1 (GPIO5)** | → 输出 | LoRa 模块 **RX** | SoftwareSerial TX，发命令到 LoRa |
| **D5 (GPIO14)** | 双向 | OLED **SDA** | I2C 数据线 |
| **D6 (GPIO12)** | → 输出 | OLED **SCL** | I2C 时钟线 |
| **3V3** | → | LoRa VCC / OLED VCC | 供电 3.3V |
| **GND** | — | LoRa GND / OLED GND | 共地 |
| **GPIO0** | 输入 | 板载 FLASH 按键 | 短按=触发节点发现，长按3s=重新配网 |
| **USB** | — | 电脑 | 烧录程序 + 调试串口(115200) |

> 注意事项：
> - LoRa 与 OLED 共用 3V3 即可，功耗不大，无需外接电源
> - D2/D1 方向已标（D2 收 LoRa 的 TX，D1 发 LoRa 的 RX），**不要接反**
> - 若用 ESP32 板：LoRa 用硬串口 UART1（RX=GPIO4/TX=GPIO5，可 115200），OLED 用 SDA=GPIO18/SCL=GPIO19，见 `hw_cfg.h`

### 5.2 节点（STM32 BH-F103）接线

| STM32 引脚 | 方向 | 连接到 | 说明 |
|------------|------|--------|------|
| **PA2 (USART2_TX)** | → 输出 | LoRa 模块 **RX** | 发命令到 LoRa |
| **PA3 (USART2_RX)** | ← 输入 | LoRa 模块 **TX** | 收 LoRa 数据 |
| **PA9 (USART1_TX)** | → 输出 | 调试串口 RX | 调试输出（USB-TTL 转接） |
| **PA10 (USART1_RX)** | ← 输入 | 调试串口 TX | 调试输入 |
| **PA0** | → 输出 | **LED** 正极（串限流电阻） | 远程控制灯 |
| **PB15** | → 输出 | HC-SR04 **Trig** | 超声波触发脚 |
| **PA8** | ← 输入 | HC-SR04 **Echo** | 超声波回波脚（TIM1_CH1 捕获） |
| **PB13** | 双向 | QMC5883P **SDA** | 地磁 I2C 数据（软件 I2C） |
| **PB14** | → 输出 | QMC5883P **SCL** | 地磁 I2C 时钟（软件 I2C） |
| **PB12** | ← 输入 | QMC5883P **DRDY** | 地磁数据就绪 |
| **5V/3V3** | → | 各模块 VCC | 超声波 5V，地磁 3V3 |
| **GND** | — | 各模块 GND | 共地 |

> 注意事项：
> - 超声波 Trig 是 **PB15**（不是 PA0，PA0 是 LED 的），接反会测不到距离
> - 地磁是**软件 I2C**（GPIO 翻转模拟时序，无硬件绑定）：默认引脚为 SDA=PB13 / SCL=PB14 / DRDY=PB12，
>   如换到别的 IO，需同步修改 `bsp_qmc5883p.h` 里的引脚宏定义再编译烧录
> - LoRa 模块电平与 STM32 同为 3.3V 逻辑，直连即可

## 六、完整上手指南

> 从零到跑通整个链路：环境准备 → LoRa 配置 → 网关烧录 → 节点烧录 → 平台配置 → 上电验证。
> 按顺序执行即可，共约 6 步。

### 6.0 环境准备

| 工具 | 用途 | 下载/说明 |
|------|------|-----------|
| **Arduino IDE 2.x** | 编译烧录网关程序 | arduino.cc，需装 ESP8266 开发板包（Board Manager 搜索 esp8266） |
| **Keil MDK** | 编译烧录 STM32 节点程序 | 需 STM32F1 器件支持包 |
| **串口助手**（如 SSCOM/XCOM） | 配置 LoRa 模块 AT 指令 | USB-TTL 模块一个 |
| **USB-TTL 转换器** | 连接 LoRa 模块/调试 | CH340/CP2102 均可 |
| **OneNET Studio 账号** | 云端产品/设备配置 | open.iot.10086.cn |

> 网关依赖库（PubSubClient / ArduinoJson / Adafruit SSD1306 等）清单见系统设计文档.md 第九章。

### 6.1 LoRa 模块配置

用 USB-TTL 连接各 LoRa 模块，串口助手 9600 波特率发送 AT 指令：

**公共配置（所有模块都要设）：**
```
AT+MODE1       ← 定点传输
AT+LEVEL6      ← 空中速率 37500bps
AT+CHANNEL00   ← 信道 0 (433.15MHz)
AT+BAUD3       ← 串口 9600
AT+RESET       ← 重启生效
```

**地址（各模块不同）：**
```
网关: AT+MAC00,00    ← 地址 0x0000
节点1: AT+MAC00,01  ← 地址 0x0001
节点2: AT+MAC00,02  ← 地址 0x0002
```

### 6.2 网关烧录（Arduino IDE）

1. 打开 `Gateway/Gateway.ino`
2. 选择板型：**NodeMCU 1.0 (ESP-12E Module)**
3. Flash Size：**4MB (1M SPIFFS)**
4. 接线：LoRa 接 D1/D2，OLED 接 I2C（SDA=D5, SCL=D6），详见本文**第五章 接线说明**
5. 确保 `platform_cfg.h` 中 OneNET 配置正确（WiFi 账号改由配网页面配置）
6. 编译烧录，打开串口监视器（115200）查看日志
7. **WiFi 配网**：首次上电自动进入配网模式（热点 `ParkingGateway_Config`），手机连接后浏览器访问 `192.168.4.1`，选择 WiFi 并输入密码；之后长按板载 FLASH 键（GPIO0）5 秒可重新配网

### 6.3 节点烧录（Keil MDK）

1. 打开 `Project/RVMDK（uv5）/BH-F103.uvprojx`
2. 修改 `BSP/lora_node.h` 中的 `LORA_SUB_DEVICE_NAME`（节点1=Park001，节点2=Park002）
3. 编译烧录
4. 上电后观察串口调试输出（节点端 OLED 已停用，各节点状态集中在网关 OLED 显示）

### 6.4 OneNET 平台配置

1. 在 [OneNET Studio](https://open.iot.10086.cn/studio) 创建子产品（04kjwU9TC7）和设备（Park001/Park002）
2. 将子设备绑定到网关 PGW001 的子设备拓扑
3. 为子设备创建物模型属性（标识符见系统设计文档.md 第 8.2 节）

### 6.5 首次上电验证清单

全部烧录、配置完成后，按顺序给网关和各节点上电，逐项确认：

| # | 检查项 | 通过标准 |
|---|--------|----------|
| 1 | 网关启动画面 | OLED 依次显示 WIFI CONNECTING → SERVER CONNECTING → SEARCHING NODES → 主界面 |
| 2 | WiFi 连接 | 串口日志出现 `[WiFi]` 连接成功、IP 地址 |
| 3 | MQTT 连接 | 串口日志出现 MQTT 连接成功，OLED Header 显示已连接图标 |
| 4 | 节点发现 | 开机扫描后 OLED FOUND 计数 = 实际在线节点数 |
| 5 | 数据上报 | 节点上电后，串口日志出现 `[MQTT] 子设备上线`，随后平台能收到车位数据 |
| 6 | 下行控制 | 平台下发 LedEnable=1，节点 LED 点亮，日志出现 `[LoRa] 下发控制` |
| 7 | 掉线恢复 | 关闭一个节点，OLED 该行反显离线；重新上电，节点自动重新上线 |

> 若某一步不通过，先看串口日志定位（日志均为中文，含 `[LoRa]`/`[MQTT]`/`[WiFi]`/`[节点]` 前缀），
> 排查指引见系统设计文档.md 附录C（调试与诊断）。

## 八、技术栈

## 九、核心交互逻辑（一句话）

> **网关点名，节点回答，网关代上报。** 网关一个个轮询每个节点，收到数据后代子设备上报 OneNET。一个节点掉线不影响其他节点。
