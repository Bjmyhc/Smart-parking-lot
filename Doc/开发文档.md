## 二、注意事项与踩坑记录

### 2.1 LoRa 并发与轮询

本项目采用轮询方案，无需 LBT，但需注意：

1. **LBT**：如后续节点变多，LoRa 模块的 LBT 可避免碰撞，但轮询已够用
2. **轮询周期**：按协议各节点独立轮询，不会互相干扰
3. **丢包**：轮询机制容忍单次丢包，下轮自动补查

### 2.2 SoftwareSerial 兼容性

ESP8266 SoftwareSerial 对波特率和中断比较敏感：

- LoRa 模块串口波特率固定为 9600，参考项目空中速率 9600 不适用
- 如果波特率 115200 不稳定，建议换 ESP32（3 个硬串口）

### 2.3 MQTT 缓冲区大小

子设备批量上报(pack/post)的 JSON 最大 300 字节(identity + 8个只读属性值)：

- 使用 `mqtt.setBufferSize(2048)`，onenet_handler.cpp 已设置
- 平台下行属性设置(set) payload 通常 < 200 字节，默认缓冲区 768 字节够用

### 2.4 OneNET Token 有效期

网关 Token 的 `et=1815919855` (2027年到期)，到期后需重新生成：

- 修改 Token 在 platform_cfg.h
- 子设备 Token 存 LittleFS，到期后重新获取

### 2.5 ESP8266 内存

ESP8266 可用 RAM 约 40KB，注意控制：

- 子设备数据数组：10 个 × sizeof(NodeData) ≈ 100 字节
- 子设备证书数组：10 个 × sizeof(NodeCert) ≈ 1KB
- ArduinoJson StaticJsonDocument<512> 占用 512 字节
- MQTT + WiFi 协议栈占用约 20KB
- 其余 22KB 留给应用逻辑
- 若内存不足 > 20%，需检查 `ESP.getFreeHeap()`

### 2.6 未来升级 ESP32 适配表

| 功能点     | ESP8266              | ESP32                |
| ---------- | -------------------- | -------------------- |
| WiFi 库    | `ESP8266WiFi.h`    | `WiFi.h`           |
| LoRa 串口  | `SoftwareSerial`   | `Serial1` (硬串口) |
| Flash 存储 | LittleFS (4MB)       | LittleFS (8~16MB)    |
| WebServer  | `ESP8266WebServer` | `WebServer`        |
| 代码兼容性 | 基准                 | 基本可移植           |

### 2.7 AP 配网与 MQTT 冲突

AP 配网期间 ESP8266 同时开启 AP 和 WiFi STA，MQTT 不会连接：

- 配网页面显示状态时不连 MQTT，仅显示节点在线信息
- 配网成功自动切换回 STA 模式
- 子设备证书存在 LittleFS，配网不影响证书

### 2.8 OTA 与 LoRa 冲突

子设备 OTA 升级会占用 LoRa 空口，需注意：

- OTA 期间暂停其他 LoRa 轮询，避免冲突
- OTA 分包间隔适当加长
- 子设备 OTA 完成后重启会自动重新注册

### 2.9 OLED 8x8 字库 PROGMEM 陷阱 (重要!)

8x8 点阵字库存 `PROGMEM` 后，ESP8266 core/Flash 的字节对齐要求，直接 `[]` 访问
`.irom.text` 段会触发 `Exception(3) LoadStoreError` 导致无限重启。

- 方案: 字库约 760 字节直接放 RAM，代价可接受
- 镜像问题: 字库位序 bit0=最左列, 必须用 `drawPixel` 按 `1 << col` 绘制,
  不能用 Adafruit `drawBitmap`(bit7=最左列), 否则整体镜像

### 2.10 编码规范 (重要, 2026-08-09 新增)

| 代码端                        | 工具链      | 编码                        | 说明                                                   |
| ----------------------------- | ----------- | --------------------------- | ------------------------------------------------------ |
| **网关端** (Gateway/)   | Arduino IDE | **UTF-8**             | Arduino IDE 2.x 用 UTF-8 编码, 写 GBK 会乱码或编译错误 |
| **节点端** (STM32 节点) | Keil MDK    | **GB2312** (ANSI/GBK) | Keil 默认用 GB2312 编码显示中文, 写 UTF-8 会乱码       |

注意规范:

- 网关端全部代码用 UTF-8: `Gateway.ino` + 所有 `.cpp/.h`
- 节点端全部代码用 GB2312: `lora_node.c/.h` 等
- 两端共享协议文件 `lora_protocol.h` 在网关端属于**网关代码**, 用 UTF-8
- 建议**不带 BOM** 的 UTF-8 (带 BOM 会导致一些工具解析异常)
- 检查方法: 用 VS Code / Trae 打开, 中文显示正常 = 编码正确
- 曾发生: 编码错误导致中文永久丢失(开发文档.md 损坏事故), 务必用正确工具保存

### 2026-08-11 LoRa 链路稳定性联调与关键修复（当前阶段）

- **节点模块供电问题**：模块接 3.3V 供电接近下限，发射电流（约 118mA）导致压降、模块复位（串口出现 "Power on"）→ 改接更靠近模块的 3.3V 电源点（缩短走线、供电质量改善）后消除
- **ACK 帧缺行结束符**：节点 ACK 响应未以 `\r\n` 结尾，网关按 `\r` 分帧等不到结束符，多个 PONG 攒满缓冲才一次性收到（表现为"积压几十秒后突然收到"）→ `LoRa_Node_SendAck` 补 `\r\n`
- **pollPhase 状态残留**：节点1 PING 通后阶段状态被节点2 继承，导致跳过 PING 直接发命令 → `advanceNextNode()` 换地址时复位轮询阶段
- **搜索重试语义统一**：`DISCOVER_PING_ATTEMPTS=3` 定义为"总尝试次数"（1 次初始 + 2 次重试），日志由"重试 x/3"改为"尝试 x/3"，消除 off-by-one 观感
- **周期轮询节流**：新增 `LORA_POLL_ROUND_MS=2000`，一轮节点扫完静默 2s 再开始下一轮，避免"节点回多快就发多快"导致空口忙
- **离线节点探测退避**：离线节点 PING 探测按指数退避逐档翻倍（2s→4s→8s→16s→32s→64s 封顶），防止坏节点/长期断电节点空耗空口并拖慢轮询；收到任何有效帧即恢复快节奏
- **OLED 第三屏修复**：扫描画面（SEARCHING NODES）强制 0.45s 快刷，FOUND 数字实时跳动；最短展示时长 1s → 3s，让用户看清搜索过程
- **按键交互优化**：短按阈值 1s → 3s（松手触发节点搜索）、长按 3s → 5s（进入配网）、新增 30ms 软件消抖，消除抖动误触发/漏触发

### 2026-09-05 链路稳定性收尾 + 下行服务化 + 拍照联动（与摄像头固件/APP 同期）

- **MQTT 假死根治定稿**：库 keepalive=30s（60s 无数据判死），去掉早期业务级 PING；`onenet_disconnect()` 统一收口；掉线边沿打印 `[MQTT] 连接断开(state=x)` 触发自动重连；DNS→IP 首次解析成功后静态缓存（防 WiFi 重连后 mqtt.connect() 长时间 DNS 阻塞）；连接加入 stall 补偿。另发现 mqtt.connect() 在 std:: 行上 freeze 的问题被上述手段吸收
- **节点离线判定防误杀**：`checkNodeTimeout` 判定阈值取"理论动态超时 ×2"（单节点 12s/双节点 18s），LoRa 偶发丢一帧不再把活节点判成离线
- **LoRa 协议 v3（18B）**：NodeData 移除 LedEnable，LED 控制改走下行服务；节点回声当前生效的僵尸阈值/距离阈值；帧末带 seq+crc16 防错帧
- **下行控制服务化**：主通道 `thing/sub/service/invoke` 下发 SetLed/SetZombieThreshold/SetSensorDistance，回 invoke_reply（Result=是否识别/执行）；兼容通道 `thing/sub/property/set` 写阈值属性；订阅数 3→6
- **低发射功率供电问题**：LoRa 调 0dBm 后节点端供电压降致模块复位重启；采纳复位计数 + 上电原因诊断（POR/PIN/IWDG/WWDG/SW）辅助定位
- **摄像头 TriggerCapture + App 自动拍照**：拍照识别链路正式落地（见 APP开发文档 4.6/4.7、系统设计文档附录E.1），早期 CapturePlate 备用方案废弃（方案全文已删，决策备忘见系统设计文档附录E）
