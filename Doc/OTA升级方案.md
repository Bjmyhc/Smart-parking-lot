## 1. 目标与背景

节点侧无法直接联网，需要支持**远程固件升级**，完整链路如下：

```
OneNET平台(固件仓库)
   |  HTTP 下载(支持断点续传)
   v
ESP8266 网关 → LoRa 128B/包 分包下发 → STM32 节点 BootLoader
                                         | 写内部Flash + CRC校验
                                         v
                                   跳转新固件(APP)
```

## 2. Flash 分区规划

### STM32F103C8T6 Flash 布局（64KB）

| 区域 | 起始地址 | 大小 | 说明 |
|------|----------|------|------|
| BootLoader | `0x08000000` | 16KB（页0~15，实际占用约 8.2KB） | 常驻，永不覆盖，升级时判断标志跳转 |
| 节点配置区 | `0x08003000` | 1KB（页12） | 节点身份（LoRa地址/产品ID/设备名），首启落盘，OTA 不触碰 |
| APP | `0x08004000` | 47KB（页16~62） | 用户固件区，OTA 直接覆写（`APP_MAX_SIZE=47KB`） |
| OTA 标志页 | `0x0800FC00` | 1KB（页63） | 存储升级标志：`0xA5A5A5A5`=待升级，`0x00000000`=完成 |

```
地址空间: STM32F103C8T6  Flash 64KB (0x08000000 ~ 0x0800FFFF)
========================================================================
0x0800FFFF ┌──────────────────────────────────────────────┐
           │ 升级标志页  1KB  (页63)                        │ ← OTA_FLAG_ADDR
0x0800FC00 ├──────────────────────────────────────────────┤     0xA5A5A5A5=待升级
           │                                              │     0x00000000=完成
0x0800FBFF │ ┌──────────────────────────────────────────┐ │
           │ │                                          │ │
           │ │        APP 固件区  47KB = 0xBC00          │ │
           │ │    (0x08004000 ~ 0x0800FBFF)             │ │ ← APP_MAX_SIZE
           │ │   OTA 仅擦写这一段, 掉电损坏可被 Boot 救回  │ │     最高地址
0x08004000 │ └──────────────────────────────────────────┘ │
           ├──────────────────────────────────────────────┤
           │  Boot 保留 (0x08003400, 3KB 余量)             │
0x08003400 ├──────────────────────────────────────────────┤
           │  配置区 1KB (页12)                            │ ← NODE_CONFIG_ADDR
           │  magic 0xA5C3A5C3 + CRC32                    │     LoRa地址/产品ID/设备名
0x08003000 ├──────────────────────────────────────────────┤     Boot首启落盘, OTA 不触碰
           │                                              │
           │  BootLoader 代码区 (~8.2KB, 上限 12KB)        │ ← 常驻, 永不覆盖
           │  0x08000000 ~ 0x08002FFF                     │     上电/复位入口
0x08000000 └──────────────────────────────────────────────┘
```

要点：
- **低地址 48KB**（0x08000000~0x0800BFFF）：Boot + 配置区 + 保留区，OTA 永远不会写到这里
- **APP 区 47KB**（0x08004000~0x0800FBFF）：OTA 唯一擦写目标，实际固件约 23KB，余量充足
- 配置区 0x08003000 落在 Boot 的 16KB 分配内（实际 Boot 只占前 12KB），所以**配置区既不占 APP 空间、也不被 OTA 擦除**，天然隔离

### APP 代码修改

APP 编译时需调整：
- **Flash 起始地址**: `0x08004000`
- **中断向量表偏移**: `SCB->VTOR = 0x08004000`
- **IROM1 起始**: `0x08004000`，**大小**: `0x0000BC00`（47KB，须与 `boot_cfg.h` 的 `APP_MAX_SIZE` 一致）

## 3. 固件文件头格式

OTA 固件文件（`.bin`）前 12 字节为文件头，由打包工具 `Tool/fw_pack.py` 生成：

```c
typedef struct {
    uint16_t magic;      // 魔数 0xA55A
    uint16_t version;    // 固件版本号（如 0x0001 = v1.0）
    uint32_t length;     // 代码段长度(字节)
    uint32_t crc32;      // 代码段 CRC32 (多项式 0xEDB88320)
} FwHeader_t;
```

## 4. 数据传输协议（Xmodem 变体 + LoRa 定点）

### 每包 133 字节格式

```
[SOH(1B)] [SeqH(1B)] [SeqL(1B)] [Data(128B)] [CRCH(1B)] [CRCL(1B)]
```

| 字段 | 大小 | 说明 |
|------|------|------|
| SOH | 1B | `0x02` 数据包起始标记 |
| Seq | 2B | 16位序号，从 1 递增，大端 |
| Data | 128B | 固件数据，最后不足 128B 用 `0x1A` 填充 |
| CRC16 | 2B | XMODEM 多项式 `0x1021`，覆盖 128B 数据 |

### 控制字符

| 符号 | 值 | 含义 |
|------|-----|------|
| SOH | `0x02` | 数据包开始 |
| ACK | `0x03` | 确认接收正确 |
| NAK | `0x15` | 否定（CRC 错误） |
| EOT | `0x04` | 传输结束 |
| CAN | `0x18` | 取消传输 |

### LoRa 链路层帧头

每包前附加 3 字节帧头实现定点传输：

```
[AddrH(1B)] [AddrL(1B)] [CH(1B)] + 数据
```

- 网关地址: `0x0000`，信道: `0x00`（433.15MHz）
- 节点回复 ACK/NAK/EOT/CAN 时也需带网关地址帧头

## 5. 完整升级流程

### 阶段 0：触发准备

网关接收 OneNET 平台 OTA 任务或 Web 管理页面触发，调用 `ota_start(nodeId, url, version)`。

### 阶段 1：触发节点复位

```
网关 → 节点: AT+OTA=start,v1.0\r\n
          (等待 ACK，2s 超时重发，最多 3 次)
节点 → 网关: AT+OTA:ack
```

### 阶段 2：等待节点复位

网关等待 5 秒（`OTA_NODE_RESET_WAIT_MS = 5000`），让节点复位进入 BootLoader。

### 阶段 3：下载固件到网关

```
网关 HTTP 下载: 固件 URL → LittleFS (/ota_firmware.bin)
平台 OTA 模式: 固件已预下载，跳过此步
```

### 阶段 4：Xmodem 分包发送

```
循环: 读 128B → 组装 133B 包 → LoRa 发送 → 等待 ACK
  ACK → 序号+1，继续
  NAK → 重发当前包（最多 3 次）
  CAN → 取消传输
  超时(2s) → 重发当前包（最多 3 次）
```

### 阶段 5：结束传输

```
所有包发送完毕 → 发送 EOT (0x04)
等待节点最终 ACK（CRC32 验证通过）/ NAK（验证失败）
超时 2s 也视为完成
```

### 阶段 6：清理

- 删除临时文件 `/ota_firmware.bin`
- 升级成功后标记节点需要重新下发阈值

## 6. 节点 BootLoader 接收逻辑

### 启动判断

```
上电读 OTA 标志:
  0xA5A5A5A5 → 强制进入 OTA 接收模式
  其他       → 等待 2s:
    - 按键(PA0 低电平) → 进入 OTA
    - LoRa 收到 'O'   → 进入 OTA
    - 超时未触发       → Load_APP(0x08004000)
```

### 接收流程

1. 擦除 APP 区（47KB，逐页 1KB，按 `APP_ADDR` ~ `APP_ADDR + APP_MAX_SIZE` 范围）
2. 循环接收 Xmodem 包，每包超时 1s，总超时 120s
3. 首包解析 12B 固件头（验证魔数 `0xA55A`）
4. 每包 CRC16 校验通过 → ACK，失败 → NAK
5. 收到 EOT 后，对整段固件做 CRC32 软件校验
6. CRC32 通过 → 写完成标志 → 回复 ACK → 跳转 APP
7. CRC32 失败 → 回复 NAK

### 断电保护

- 升级过程中断电，APP 区不完整，下次上电进入 BootLoader
- BootLoader 检测到标志页为 `0x00000000`（无待升级），但 APP 校验失败时，**停留在 BootLoader 等待下一轮 OTA**
- 永不"变砖"
