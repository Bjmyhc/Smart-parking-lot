## 三、根因（实测证据，已钉死）

### 3.1 崩溃现场

关键点：`dl_model_base.cpp:170` 的 `m_model_context->add_tensor(..., m_fbs_model->get_operation_parameter(node_name, j))` —— **这里传进来的 `node_name` 是 `/Pow`、`/ReduceMean` 这类算子节点**，而 esp-dl 不认识它们，拿参数时命中空指针。

### 3.2 决定性证据 —— 算子白名单比对

esp-dl 3.1.5 支持的算子全集定义在 `managed_components/espressif__esp-dl/dl/module/include/dl_module_creator.hpp`（第 110–156 行注册）。

实测扫描 `lprnet_s3.espdl` 的 46 个节点：

```

算子分布: {'Conv': 16, 'MaxPool': 3, 'AveragePool': 3, 'DequantizeLinear': 4,
           'Pow': 4, 'QuantizeLinear': 4, 'ReduceMean': 5, 'Slice': 2,
           'Div': 4, 'Concat': 1}

>>> 不在 esp-dl 3.1.5 白名单内的算子节点（共 9 个）:
    [ 6] Pow          /Pow
    [10] ReduceMean   /ReduceMean
    [17] Pow          /Pow_1
    [21] ReduceMean   /ReduceMean_1
    [33] Pow          /Pow_2
    [37] ReduceMean   /ReduceMean_2
    [38] Pow          /Pow_3
    [41] ReduceMean   /ReduceMean_3
    [45] ReduceMean   /ReduceMean_4

官方对照 : model.espdl   节点总数: 3  →  {'Gemm': 3}  → 全部在白名单内
```

**`Pow` 和 `ReduceMean` 均未在 `dl_module_creator.hpp` 注册。** 崩溃发生在解析算子输入参数阶段，与 `A15="Vari"`（引用了 `PPQ_Variable_*` 参数张量）完全吻合。

### 3.3 结论

> **根因：`lprnet_s3.espdl` 中包含 esp-dl 3.1.5 未实现的算子 `Pow`(×4) 与 `ReduceMean`(×5)，导致 `dl::Model` 构造阶段在 `get_operation_parameter` 取参时解引用空指针崩溃。**
>
> **性质：导出端（esp-ppq 1.3.11 导出）与运行端（esp-dl 3.1.5）能力不匹配，不是运行环境问题。**

### 3.4 次要猜想（未验证，优先级低）

自产模型的 `PPQ_Variable_*` 参数张量中约 20 个 **dims 为空 `[]`** 的标量（官方模型全部 dims 非空）。而 `TensorBase::set_shape` 断言 `shape.size() > 0`，理论上也可能触发断言。但当前崩溃已由 3.2 解释，此项留作修复后的回归观察点。

## 四、修复方案（按推荐顺序）

### 方案 A（推荐，最稳）：改写模型结构，消除不支持算子

`Pow` + `ReduceMean` 是 LPRNet 里 **GlobalAveragePool → 除以 24（`H`）** 这类「全局平均池化」表达式的副产物。搞清 `quant_espdl.py` 里的导出链路：

- 把 `Pow(x, 2)` / `sqrt(mean(pow))` 这类写法（典型来自 `x.pow(2).mean()` 形式的 RMS / 归一化）替换为 **`F.avg_pool2d(x, x.size()[2:])`** 或 `nn.AdaptiveAvgPool2d(1)`，导出即成为 `GlobalAveragePool`（在白名单内）；
- 若确实需要「除法归一化」，先做 `AdaptiveAvgPool2d(1)` 得到 `GlobalAveragePool`，再乘一个常量（走 `Mul`，在白名单内），**不要用 `Div + ReduceMean` 组合**。

改完重新导出 `.espdl`，重烧验证。这是唯一不改变运行端、能彻底解决的路径。

### 方案 B：换支持这些算子的 esp-dl 版本 / 自己补算子

- 检查是否有更新的 esp-dl（> 3.1.5）已把 `Pow` / `ReduceMean` 纳入支持；
- 或在 `dl_module_creator.hpp` 里自行注册一个 `ReduceMean` 模块（工作量大，需实现 int8 前向 + 量化参数推导，不推荐）。

### 方案 C：导出前用 ONNX 图优化做算子融合/替换

在 ONNX 层用 `onnx-simplifier` 或手写 graph surgery，把 `Pow`/`ReduceMean` 子图替换成 `GlobalAveragePool`，再喂给 esp-ppq 量化。本质与方案 A 等价，但不必改训练代码。

## 五、还需要修的运行端问题（与崩溃独立，但有实锤）

monitor 日志证实 **`sdkconfig.defaults` 完全没生效**——因为工程里 `sdkconfig` 已存在，而 `sdkconfig.defaults` **仅在 `sdkconfig` 不存在时**才被读取。

实测当前状态与官方要求差距：

| 配置项 | 当前 | 应为（官方 `sdkconfig.defaults.esp32s3`） |
|---|---|---|
| Flash 模式 | `DIO` | `QIO` |
| CPU 频率 | `160 MHz` | `240 MHz` |
| 指令 Cache | 未指定（32KB 默认） | `INSTRUCTION_CACHE_32KB=y` |
| 数据 Cache | 未指定 | `DATA_CACHE_64KB=y` |
| Cache Line | 未指定 | `DATA_CACHE_LINE_64B=y` |
| RTC 内存 | 未指定 | `ALLOW_RTC_FAST_MEM_AS_HEAP=n` |

**处理方式（二选一）**：

1. 删除 `PlateRecognitionIDF/sdkconfig`，让 `sdkconfig.defaults` 重新生成 —— 但会丢手工改过的项，建议先备份；
2. 直接在 `sdkconfig` 里补齐上述 6 项（更稳）。

> 注：ESP-DL 大量算子（`dl_tie728_s8_*.S`）对 cache 配置与 CPU 频率有硬性要求，160MHz / DIO 会拖慢甚至影响正确性。修算子问题的同时务必一起改掉。
